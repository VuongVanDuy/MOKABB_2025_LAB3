# Задача
1. Взять любой дистрибутив любой общедоступной ОС (Windows, Mac OS или ОС на базе Linux) и установить его в виртуальную машину.
2. Написать на любом языке программирования программу, которая выполняет «полезную нагрузку», имитируя полезную нагрузку ВПО. Программа должна быть собрана как исполняемый файл и не требовать внешних зависимостей для запуска (читайте — легко переноситься, пересылаться и так далее).
3. При первом запуске программа должна закрепиться минимум двумя разными способами в рамках выбранной ОС, чтобы пережить перезагрузку, а затем удалить своё тело из места, где был проведен первый запуск.
4. После перезагрузки и/или по наступлению события, назначенного вами при закреплении, должна выполниться полезная нагрузка. Это может быть почти что угодно недеструктивное, включая запуск программ, открытие окон или что угодно, на что хватит вашей фантазии. ОС, соответственно, должна тоже пережить перезагрузку и не сломаться.

Предполагается, что при первом запуске для закрепления программа может быть выполнена с правами администратора. В дальнейших запусках наличие прав администратора не гарантируется.

# Ход работы
Будет реализовано две программы. Программа кейлоггер будет попадать на компьютер жертвы, запускаться (без прав root) и использовать один или несколько вариантов закрепления. Также будет программа - центр управления. Она будет запускаться на компьютере злоумышленника и передавать/получать сигналы от программы на компьютере жертвы. Схема работы программ:
```
Центр     |--> Start/Stop keylogger -->| Кейлоггер
управления|<--  System Information  <--|
          |<--      Alive Signal    <--|
          |<--        Key info      <--|
```
Также у программы злоумышленника есть функция очистки буфера (все переданные символы очищаются) и функция выхода из программы.
Программа на компьютере жертвы до первого запуска выглядит как один `.elf` файл, для удобства названный `payload`. При запуске, программа запускается, удаляет своё тело и создаёт свой файл бэкапа в `/home/user/.cache/backups/`. Как видно, кроме того, что папка для бэкапа скрыта сам файл бэкапа будет назван исходя из хэша зловреда. Это несет в себе две функции:
1. Однозначно определять файл бэкапа и избежать дублирования
2. Запутать пользователя непонятным для него названием
Теперь программа активна и как только будет запущена программа центра управления, будет послан сигнал для старта работы программы. Будет вывод информации о системе жертвы.

Далее будет собираться информация о нажатиях клавиш на компьютере жертвы.
# Результат
Были написаны две программы. Одна - реализующая функции кейлоггера, вторая - программа центр управления. Также для программы кейлоггера были реализованы два варианта закрепления.
1. Использование "фейковой" иконки браузера, для запуска вредоноса
2. Использование закрепление с помощью systemd

Использование:
```
usage: payload [-h] [--only-systemd | --only-cron | --only-desktop]
               [--no-systemd] [--no-cron] [--no-desktop] [--all-enable]
               [--all-disable]

Payload runner. Default installs only desktop entry persistence.

optional arguments:
  -h, --help      show this help message and exit
  --only-systemd  Install only the systemd unit (no cron, no desktop entry)
  --only-cron     Install only the cron job (no systemd, no desktop entry)
  --only-desktop  Install only the desktop entry (no systemd, no cron)
  --no-systemd    Do not install systemd unit
  --no-cron       Do not install cron job
  --no-desktop    Do not install desktop entry
  --all-enable    Install both systemd and cron and desktop entry (default)
  --all-disable   Do not install any persistence mechanism
```
